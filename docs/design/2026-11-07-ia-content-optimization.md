## 0. 结论

首页现在同时讲三件事：**记忆**（日志流、卡片、检索）、**创作**（创作空间、周报）、**本地优先**（数据、BYOK、Markdown）。三件都是真的，但 H1 只讲了最泛的那一件——「一个创作助手」——于是页面读起来像又一个 AI 写作工具，而不是「先替你记住，再帮你写」的那一个。

建议按下面五步改，前两步是内容口径，后三步是信息架构：

1. **统一主张与术语**：「分身」已退役；把「创作助手 / 记忆底座 / 个人创作 AI」收敛成一句可复述的话；H1 保持现有句（已裁决 B），差异化交给副句与三条承诺。
2. **修掉绝对化口径**：删掉「数据永远留在你的机器」这类与隐私页自相矛盾的句子，改成「默认不出本机」。
3. **把「怎么用」提到「凭什么信」之前**：Hero → 怎么用 → 产出什么 → 三条承诺 → 现在/接下来 + 费用 → FAQ → CTA。
4. **让每个问题只有一个主落点**：价格、平台、隐私、内测时间不再在特性卡、FAQ、CTA 里各说一遍；FAQ 只答前面没答的。
5. **把唯一 CTA 接到真实可用的动作上**：要么部署 `edge/waitlist`，要么换成「看进度 / 提需求」，不要留一个看着能点、实际禁用的主按钮。

| # | 改动 | 类型 | 影响 | 成本 | 优先级 |
|---|---|---|---|---|---|
| 1 | 部署收集端，或把 CTA 换成可用动作 | 转化 | 高 | S | P0 |
| 2 | 修「永远留在你的机器」等绝对句 | 口径 | 高 | S | P0 |
| 3 | 统一「助手/底座」术语（H1 不动） | 主张 | 高 | S | P0 |
| 4 | H2 加产品词与副句；删英文硬编码 eyebrow | 可扫描性 | 中 | S | P0 |
| 5 | 02 与 03 换位，特性区改成「三条承诺」 | IA | 高 | M | P1 |
| 6 | 新增「现在/接下来 + 费用」带，吸收路线图与价格 | IA | 高 | M | P1 |
| 7 | FAQ 从 6 问重复改为 7 问残余，补平台/闭源/差异 | 内容 | 高 | M | P1 |
| 8 | 导航加 3 个锚点（或页内目录） | 导航 | 中 | S | P1 |
| 9 | 新增 `/changelog/`，补 FAQPage 与标题描述 | SEO/信任 | 中 | M | P2 |
| 10 | 内容模型改数组、状态机机检、英文转写 | 工程 | 中 | L | P2 |

> 如果只做一件：先修 CTA 与「永远」两处。前者决定有没有转化，后者决定这个站点的诚实口径是否站得住。

## 2. 诊断

### 2.1 主张分裂：一句话里有三种自称

- H1 说「创作助手」（`hero.json` 的 `title1/title2`），Meta 标题已在 2026-11-07 按裁决从「创作分身」改为「创作助手」，JSON-LD 说「个人创作 AI」，副句说「记忆底座」。
- 全站最锐利的一句在 Meta 里、不在页面上：**「通用 AI 帮你写作，Wrisp 为你创作。」**（`meta.json` 的 `docDesc`）
- 演示内容是工作场景：客户回话、竞品动态、评审结论、周报（`flow.json`），但文案用「创作」；读者会问：这是给写小说的，还是给写周报的？

后果：访客能用一句话复述「又一个 AI 写作助手」，但复述不出「它先记住，再帮你写」。这是首页最大的信息损失。

### 2.2 顺序错位：先要求核验，再解释产品

`Home.astro` 的装配顺序是 Hero → **三件可核验的事** → 工作流 → 产物。第二块就把「数据归你 / Community 免费 / 模板与技能」端上来，标题还是「三件你现在就能核验的事」——这是**信任与条款**，不是产品能力。读者还没看懂它怎么工作，就被要求核对承诺；等走到产物区，已经滚过两屏。

后果：首屏之后的说服力断档；最强的产物证据被推到页面中段；「三件可核验」因为标题抽象，实际点击/阅读意愿低。

### 2.3 问题重复：FAQ 在替前面的区块还债

| 问题 | 现在的落点 | 重复次数 |
|---|---|---|
| 数据会不会上传 | 特性卡 1 + FAQ Q1 + 隐私页 | 3 |
| 要多少钱 | 特性卡 2 + FAQ Q2 | 2 |
| 现有笔记怎么办 | 特性卡 1 + FAQ Q3 | 2 |
| 内测什么时候发 | CTA 副句 + FAQ Q6 | 2 |

FAQ 六问里四问是前面的重复；真正没答的反而缺席：**支持哪些平台**（只在 JSON-LD 里）、**闭源凭什么信**（只在隐私页副句里）、**和通用 AI/云笔记有什么不同**（只在 Meta 里）。

后果：页面显得长而重复；FAQ 没有承担「补漏」的职责，反而成了第二个特性区。

### 2.4 绝对化口径：营销句和隐私页互相拆台

- `meta.json` 的 `docDesc`：「数据**永远**留在你的机器。」
- `hero.json` 的 `sub`：「数据留在你的机器。」
- `README.md` 的简介同样写「数据永远留在你的机器」。

而隐私页逐条列出会出网的路径：云端 BYOK、属地 IP、更新检查、表单邮箱、模型下载（`priv.json` 的六行表）。FAQ Q1 也明确说「默认不会」。**「永远」是假的，「默认」才是真的。**

后果：这不是措辞问题，是可信度问题。一个把「可验证的承诺」当卖点的站点，首页第一段就和自己的隐私页冲突；懂行的读者会立刻降低信任。

同类待复核项：

- `faq.json` Q2：「Community 免费且**功能完整**」——特性卡写的是「当前阶段的能力完整可用」，多了「当前阶段」这个限定，FAQ 少了。
- 产物区「周报」用现在时（「按你选的模板把这一周组织成稿，直接拿去发」），而 2026-11-03 设计稿 §3 的前提核实把「周报可用现在时」判为 ❌（链路尚未落地）。若 11-03 后已落地，请更新那条前提；若没有，这是过度承诺。

### 2.5 转化断点：唯一的主按钮通向一个禁用表单

- `WaitlistForm.astro` 由 `PUBLIC_WAITLIST_ENDPOINT` 决定是否可提交；`.env.example` 里该值为空，于是输入框与按钮全部 `disabled`，占位符写「暂不可提交」。
- 但导航、Hero、CTA 三处仍写「加入内测」；CTA 副句仍写「可下载版本就绪时会在这里说」；表单按钮也是「加入内测」，只有邮箱占位符换成了「暂不可提交」——**承诺了一个做不到的动作，却没有一处解释为什么**。
- 关闭态没有说明行（11-06 裁决撤下），于是用户只看到一个蓝色的、点不动的按钮，不知道为什么。
- 隐私页 `n3` 写「表单这一版还没有接通收件服务：你现在填的邮箱不会离开浏览器」——可输入框是禁用的，「填」这个动作根本不存在。这句话在技术上没错，在体验上是空话。
- 更细的漂移：`.env.example` 与 `README.md` 仍写「页面上说明收集通道尚未开通」，可那条说明已经在 11-06 撤下。文档、注释、UI 三处口径不一致。

后果：全站唯一的转化动作是死路；而它恰好发生在用户已经被说服、准备行动的那一刻。

### 2.6 可扫描性与双语细节

- **H2 全是隐喻**：「三件你现在就能核验的事 / 碎片，变成你的知识 / 整理是过程，产物才是你能用的东西 / 先回答六个最常被问的 / 先让它记住今天。」只读 H1+H2，读者得不到任何产品名词、平台、价格或差异。
- **中文页混英文标签**：产物区四张卡的 eyebrow 是硬编码的 `INFO CARDS` / `TO-DO LIST` / `WEEKLY REPORT` / `CREATION SPACE`（`Proofs.astro`），既没本地化，又和下面的 `h3` 重复。
- **默认语言是英文**：`astro.config.mjs` 的 `defaultLocale: 'en'`，`/` 是英文页。中文是文案的母语、也是品牌语气所在，中文读者却要先切一次语言。边缘跳转层（`edge/router/`）已有，但未部署。
- **英文是直译**：`Today, you need a creation assistant.` / `That memory core works today.` / `What blocks you the most today?` 都能读，但不像英文母语写的产品文案。

### 2.7 信任资产缺位

- 页脚「发布仓库」指向 `liqms/wrisp-releases`；按 2026-11-02 的核实，该仓库没有 release。一个空 release 页对预发布产品是负资产。
- 没有更新日志、没有「最后更新」、没有真实截图（四张产物卡是 CSS mock）、没有关于页/联系人。隐私页是站内最强的信任资产，却只在页脚有一个入口。
- FAQ Q1 提到「隐私与数据声明页逐条列出了会离开本机的路径」，但这句话是纯文本，**没有链接**。

后果：预发布阶段的信任只能靠演示与隐私页；而隐私页藏得太深，FAQ 又不指路。

## 3. 目标信息架构

### 3.1 五条原则

1. **一个问题一个主落点**：价格只在费用带，平台只在状态带，隐私主落点在隐私页，内测时间只在 CTA。FAQ 只答残余问题。
2. **先能力后条款**：先让人看懂「怎么用、得到什么」，再谈「凭什么信、多少钱、什么时候」。
3. **不新增卡片网格**：新块用两栏、清单、一行事实条；不把 12 区的卡片汤重新煮一遍，也不复活 `Diff / Persona / Pricing` 三件。
4. **区标题可扫描**：H2 带产品名词或直接是一个问题；隐喻可以留在副句里。
5. **状态驱动文案**：内测未开放 / 开放收集 / 可下载 / 公测，四种状态各自有一份 CTA 与口径，不靠人肉同步（见 §11）。

### 3.2 调整前后

```
现在：Hero → 三件承诺(3卡) → 怎么用(4步 + 3阶段) → 产物(4卡) → FAQ(6) → CTA
建议：Hero → 怎么用(4步) → 产物(4卡) → 三条承诺(3卡 + 对比句) → 现在/接下来 + 费用 → FAQ(7) → CTA
```

变化只有三处结构改动：**02 与 03 换位**、**把「三阶段」从工作流里拿出来，和价格/平台合成一条带**、**FAQ 减重复、补缺口**；另有三处文案重切（三条承诺、费用带、FAQ 答案）。没有新增一个大区块，也没有新增卡片网格。

### 3.3 每一区回答什么

| 区块 | 回答的问题 | 形态 | 主要文案资产 |
|---|---|---|---|
| Hero | 它是什么？和我有什么关系？ | 标题 + 副句 + 主 CTA + 现有双演示 | `hero.json`、`flow.json` |
| 怎么用 | 用起来麻烦吗？ | 四步 + 连接线（保留） | `work.json` 四步 |
| 产出什么 | 我能得到什么？ | 四卡（保留）+ 一句副句 | `proof.json`、`flow.json` |
| 三条承诺 | 凭什么信？ | 三卡（重切）+ 一句对比 | `features.json` |
| 现在/接下来 + 费用 | 现在能用什么？多少钱？我的电脑行吗？ | 两栏清单 + 一行费用 | 新 `now.json`（吸收 `road.json`、价格口径） |
| FAQ | 还有哪些没答？ | 七问（重排 + 补三问） | `faq.json` |
| CTA | 怎么参加？点了会发生什么？ | 标题 + 副句 + 状态化动作 | `cta.json`、`form.json` |

### 3.4 不做什么

- 不恢复「对比区」：只留一句「通用 AI 从空白页开始；Wrisp 从你已经记下的东西开始」，放在三条承诺上方。
- 不恢复「Persona 四档路由」：人群只在副句或产物副句里点一句，不做四张卡。
- 不恢复「三档定价表」：只留 Community 免费 + Pro 下一阶段两列，且不写价格数字（Pro 未定价）。
- 不把路线图整件删掉：三阶段是有价值的愿景，但压缩成「现在 / 接下来」两栏，不再占工作流的主位。

### 5.8 风格基线（参考 DeepSeek Harness）

2026-11-07 维护者给出参考页 `https://www.deepseek.com/harness/`。只取它的**结构**，不搬它的产品事实与开源/插件生态口径：

2. **首段先定义，再说动作与结果**：一句产品定义，一句「做什么 + 得到什么」，句子短，句号收。
3. **正文动词开头**：整理、生成、调用、导出；少用「它」拟人，少用「长出来 / 沉进 / 手边」这类比喻。

5. **状态前置**：内测、下一阶段、平台、默认边界，放在用户做判断的位置，不藏进 FAQ。
6. **数字具体**：4.4 GB、Windows/macOS、自己的 Key；不写「很快 / 很强 / 完整」这类形容词。
7. **英文同样短句、动词开头**，不逐字直译。
8. **H1 与 CTA 主句保留品牌语气**（已裁决），其余描述向参考页的直白收敛。

现在只有品牌、语言、CTA。对一页六屏的产品站，这不是「极简」，是「没有路标」。建议加三个锚点：

`怎么用`（→ `#how`）· `产出`（→ `#proofs`）· `常见问题`（→ `#faq`）· 语言 · `加入内测`

- 桌面显示，≤760px 隐藏文字链，只留品牌、语言、CTA；不做汉堡抽屉（NB-4 的约束仍然成立）。
- 三个 id 都已在 `check-anchors` 的白名单里，不需要改 `ALLOWED`，也不会新增 `data-shot`。
- 这是对 NB-4「导航不放章节锚点」的部分回退，必须由维护者裁决；若不回退，替代方案是 Hero 下方加一行「本页：怎么用 · 产出 · 凭什么信 · 多少钱 · 常见问题」的文字目录。

### 7.2 FAQ 深链

给每个 `<details>` 加稳定 id（`faq-data`、`faq-diff`、`faq-notes`…），页面加载时若 `location.hash` 命中，就展开对应项。这样客服、发布说明、邮件都可以直接指到某一条。不需要改 `check-anchors`（它只校验被 `href` 引用的锚点），但需要一小段脚本。

### 7.3 页脚

- 加「更新日志」（有页面后）。
- 「发布仓库」在无 release 前改为「开发进度」，指向 issues/discussions。
- 加一个真实联系邮箱或反馈入口；现在只有 GitHub。
- 版权行保留。

### 7.4 辅助页

优先级从高到低：

1. `/changelog/`（中英各一）：按日期列「已发布 / 修复 / 接下来」。它给「会在这个站点上公布」一个真实落点，给 SEO 新鲜度，也给预发布产品一个可验证的进度面。
2. `/how-it-works/`：截图、平台与运行要求、隐私路径、路线图。把首页的长尾问题接住，首页就能保持短。
3. `/about/`：谁在做、为什么闭源、怎么联系。可选，但对闭源产品是加分项。

新增页面会自动进 sitemap（`gen-seo.mjs` 读构建产物），但要在 `check-copy-coverage` 的语言分组里落地，且 `check-anchors` 要求双语首页仍有五个 id——新增页不影响这两条。

### 8.2 默认语言（已裁决：英文根 + 边缘 302）

2026-11-07 裁决：保持 `/` 英文为根，部署 `edge/router` 做 302，不把中文改成根。

**为什么不是「现在就部署」**：`edge/router` 只能挡在它自己的域名前；站点当前在 `https://liqms.github.io/wrisp-site/`，这是 Pages 项目站的子路径，Worker 没有可挂的域名。`edge/README.md` 与 `edge/router/wrangler.toml` 都写明了这一点：等最终国际域（Cloudflare DNS + 一条指向 Pages 的 Proxied 记录）定下来才谈上线。

上线时要动的地方：

1. **域名与路由**：按 `edge/router/wrangler.toml` 的模板启用 `[[routes]]`，`BASE_PATH` 视最终路径改空串；站点侧同步 `astro.config.mjs` 的 `SITE` / `BASE`，否则 canonical、hreflang、`og:url` 还指旧地址。
2. **部署**：`npx wrangler deploy --config edge/router/wrangler.toml`。
3. **收集端来源**：`edge/waitlist/wrangler.toml` 的 `ALLOWED_ORIGINS` 补上新域。
4. **索引与分享**：canonical / hreflang / `og:url` / `og:image` 随域重生成；`x-default` 仍落英文。

上线后按 `edge/README.md` 的四条手验：根路径回 `302` + `no-store`；带 `wrisp_lang=en` 不跳；`curl -sL` 两种语言内容与直连逐字节一致；`cf-ipcountry` 可见（不可见就只少一条线索，不改判定表）。

**在那之前**：URL 不动，中文读者仍手动切；不要在静态页里用 JS 猜语言（会打破「同一 URL 同一内容」）。页脚的语言提示只能作过渡，不是 302 的替代。

### 8.3 英文不是翻译，是转写

现有英文能读懂，但有几处是中文语序：

| 现在 | 建议 |
|---|---|
| Today, you need a creation assistant. | It remembers first. It's there when you write. |
| That memory core works today. | That memory works today. |
| What blocks you the most today? | What's the biggest thing in your way right now? |
| Six questions people always ask | Seven questions we hear most |
| Organizing is the process; the output is what you use | Organizing is the process. The output is what you use. |

若英文不是主市场，建议明确「英文为次级，随中文更新」；若要主攻英文，找母语编辑做一遍转写，不要逐句对译。
